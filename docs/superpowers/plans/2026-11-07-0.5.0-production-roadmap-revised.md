## 第一优先级：ECS 批量查询 API（8–10h）

### Task 1: 设计并实现 bulkQuery API

**Files:**
- Modify: `packages/ecs/index.ts` — 新增 `bulkQuery()` 方法
- Create: `tests/ecs-bulk-query.test.ts` — 单元测试
- Modify: `SPEC.md` — 文档
- Modify: `packages/ecs/README.md` — API 说明

**Interfaces:**
- Consumes: World、Token（现有 ECS API）
- Produces: 
  ```typescript
  interface BulkQueryIterator<T> {
    buffer: Entity[]
    return(): void
  }
  World.bulkQuery(...tokens): BulkQueryIterator
  ```

**实现要点**:
- bulkQuery 承诺遍历期间不增删组件
- 保留 query 快照语义，bulkQuery 是 opt-in 性能方案
- 预期性能提升：55% 快于 query()

**验证**:
```bash
npm run typecheck
npx tsx --conditions=source --test tests/ecs-bulk-query.test.ts
npm run benchmark:hot-paths -- artifacts/performance/bulkquery.json
```

## 第二优先级：长期稳定性验证（2–3h）

### Task 7: 30+ 分钟内存泄漏测试

**Files:**
- Create: `tests/e2e/endurance.test.ts` — 长时间测试

**实现要点**:
- 连续游玩 30+ 关卡（每关 ~1 分钟）
- 监测内存增长（目标 <10%）
- 收集帧率稳定性数据

**测试流程**:
1. 启动游戏
2. 循环 30 次：选择关卡 → 游玩 1 分钟 → 结算 → 重开
3. 记录内存初始值和峰值
4. 验证：`(peak - initial) / initial < 0.1`

**验证**:
```bash
npm run test:e2e -- tests/e2e/endurance.test.ts --timeout 1800000
```
