DEVELOPER GUIDE

快速上手

创建一个独立的网页 2D 游戏，从当前源码到可部署网页。

从配套源码构建引擎套件，再用 CLI 创建游戏。游戏项目独立保存源码、依赖和资源，之后的日常开发在游戏目录完成。

开始之前

需要 Node.js ≥ 22.12.0、npm、Git 和 tar，并具备基础 TypeScript、HTML、CSS 与命令行知识。以下命令使用当前仓库版本 0.5.0。Windows 与 WSL 请分别安装依赖。

1. 构建引擎套件

在引擎仓库根目录执行：

终端 · 引擎仓库
npm ci
npm run dist:release

这会检查类型、构建并打包 10 个工作区包、检查模板，并生成本地套件。套件目录位于 dist/releases/jingchuanchu-engine-0.5.0/。详细过程见从源码到独立游戏。

2. 创建一个游戏

继续在引擎仓库执行，目标目录必须不存在或为空：

终端 · 引擎仓库
node packages/tooling/dist/cli.mjs create ../my-game --preset singleplayer --style css --bundle ./dist/releases/jingchuanchu-engine-0.5.0

CLI 校验本地包摘要、解析内部依赖并复制到游戏的 vendor/，使用相对 file: 依赖。需要 Less 时将 --style css 改为 --style less。

已经拿到分发套件？

可以直接运行套件内的参考项目：

cd /path/to/bundle/starters/browser
npm install
npm run dev

或先在单独的工具目录安装配套 CLI，再创建保存 vendor 的独立项目：

npm init -y
npm install --save-dev /path/to/bundle/packages/xiaobaibaifqy-jingchuanchu-tooling-0.5.0.tgz
npx --no-install jingchuanchu create ./my-game --bundle /path/to/bundle

3. 安装与运行

终端 · 游戏项目
cd ../my-game
npm install
npm run dev

在浏览器手动访问 Vite 终端显示的地址。参考项目包括首页、关卡选择、游玩、设置和结算，游玩页管理 Canvas、HUD、暂停与重开。引擎仓库与游戏项目有各自的命令和产物。

4. 认识项目文件

位置 从这里开始修改
src/main.ts 启动应用、加载基础样式及绑定偏好。
src/app/ 应用配置、命名路由与外壳。
src/pages/ 每个页面的 TS、HTML、CSS/Less，页面私有组件及场景。
src/game/ 跨页面的会话、规则、偏好和进度 Store。
src/themes/ 主题颜色与语义图片键。
vendor/ 配套引擎安装包，随源码和锁文件一同保存。

完整职责与依赖方向见目录与文件归属。

5. 添加自己的页面

npm run generate -- page bonus --route /bonus
npm run generate -- component score-panel --page bonus
npm run generate -- scene bonus --page bonus

页面会注册到路由表。组件需显式加入父定义的 components 并在 HTML 引用；场景通过页面内的 GameCanvas 接入。可照写的完整示例见组件、表单与页面和场景与游戏循环。

6. 检查与构建网页

npm run check
npm run build
npm run preview

build 先检查目录、模板与类型，再由 Vite 输出游戏的 dist/。将其中内容部署到静态网站服务。默认使用 hash 路由；history 模式需配置入口回退和 base。联网服务端需独立部署。

保存可以重建的项目

保存源码、素材许可、vendor/、package.json 与 package-lock.json。其他协作者可以使用 npm ci 重建依赖。外部开发工具仍需要 registry 或缓存。
