DEVELOPER GUIDE

响应式与模板语法

signal、computed、effect 与原生 HTML 模板的日常用法。

可写状态与派生值

import { signal, computed } from '@xiaobaibaifqy/jingchuanchu-app/application';

const name = signal('玩家');
const score = signal(0);
const greeting = computed(() => `你好，${name()}！得分 ${score()}`);

name.set('小白');
score.update((value) => value + 10);

TS 中用函数调用读取值。signal 返回深只读快照，通过 set 或 update 替换；computed 同步推导、惰性缓存，并追踪当前实际依赖，不在计算中写入状态或等待异步结果。

副作用与清理

effect((onCleanup) => {
  const value = score();
  const subscription = externalService.observe(value);
  onCleanup(() => subscription.unsubscribe());
}, context.scope);

effect 调度到微任务，清理归 Scope。回调必须同步，重跑前执行上次清理；异步任务通过 Store 的 runTask 或显式取消机制管理。batch 合并通知且不回滚状态，nextTick 只等待视图批次。

插值、属性与事件

<h1>{{ greeting }}</h1>
<button type="button" :disabled="!canSubmit" @click="submit()">提交</button>
<input model:value="draft" />
<input type="checkbox" model:checked="enabled" />

模板自动读取 signal/computed。只允许访问 setup 暴露的成员以及结构模板的局部值，事件负载为 $event。计算、类型转换、数组处理等放在 TS 中暴露操作或派生值。

条件、列表与插槽

HTML
<template when="valid">
  <span>可以提交</span>
</template>
<template each="item of items" key="item.id">
  <span>{{ item.name }}</span>
</template>
<slot name="actions"><span>默认操作</span></slot>

结构模板使用 when、each 与稳定 key。组件投影使用显式命名插槽。完整语法及作用域约束见组件模板契约；组合表单与页面示例见组件、表单与页面。

子组件在父定义的 components 中注册；HTML 使用 kebab-case 属性名。输入为只读数据，输出为类型化事件，model 对应可写目标。只读 Store.state 和 computed 不可直接作为双向目标，需本地草稿或 writableModel 适配。

普通数据与能力引用

signal、普通输入和场景 props 保存普通数据。函数、DOM、图像、驱动和 Store 实例不能放入快照状态。GameCanvas 的 scene/options 为显式引用输入；页面通过普通函数返回 scene 定义并保留稳定 options。

复杂表单数字和多选转换采用 writableModel，数字无效草稿通过 validation 读取。程序写回不会合成用户事件。详情见应用 API 使用契约。
