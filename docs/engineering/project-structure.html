独立游戏目录

my-game/
  src/
    main.ts
    app/                  app-config、app-routes、app-shell 三文件
    pages/
      play/               play-page 三文件、play-scene、私有 hud/
      home/               首页三文件
      settings/           设置页三文件
    game/                 跨页面规则、会话、偏好与存档定义
    components/           真正复用的 UI 三文件组件
    themes/               默认及派生主题与换肤图片
    assets/               不随主题变化的公共资源
    styles/               全局基础样式
  public/                 静态资源与许可
  vendor/                 本地引擎安装包
  jingchuanchu.json        项目配置
  package.json
  package-lock.json

account/ 只在接入认证时创建。页面私有组件放页面旁，跨页面游戏业务进 game/，通用 UI 进 components/。不创建空目录或全局杂物目录。

命名和依赖方向

  • 目录与业务文件采用小写 kebab-case，例如 play-page.ts/html/css；三文件同主名。
  • 定义导出使用 PascalCase，例如 PlayPage；普通函数和值使用 camelCase。
  • app 负责装配；pages 连接 UI 与业务；game 不依赖 DOM、pages 或 app。
  • 公共组件不导入页面、游戏内部或 Engine；数据通过 input、output、model 传递。
  • 类型跟随其业务归属；复杂度需要时才拆分，避免集中维护一个全局 AppState。

维护文档的位置

所有开发者文档写在本目录站点的 HTML 中。docs/index.html 是唯一手册入口，docs/api/index.html 是 API 索引。页面元数据由 scripts/docs/pages.json 管理，导航与公共布局由 scripts/docs/site.mjs 维护，公共 API 从当前源码提取。原有 Markdown 手册、旧版本教程和发布说明入口已经移除。

根 README、各包 README 和模板 README 只保留必要的项目识别、命令及站点指引。SPEC.md 和 tasks/ 是实施工作文件，职责见规格与执行流程。
