ENGINEERING HANDBOOK

架构与能力地图

以应用组织界面，以 Engine 和 ECS 驱动玩法，按需接入浏览器能力。

运行时分层

应用层Application · Component · Router · Store · Service
游戏能力GameCanvas · Scene · Assets · Theme · Audio · Save
运行内核Engine · Scope · ECS · Canvas 2D · Input

应用 API 从 @xiaobaibaifqy/jingchuanchu-app/application 导入。UI 组件通过输入、输出和 model 通信；页面拥有场景和 Canvas。核心 ECS、调度与模块不反向依赖应用、开发工具或具体游戏。

生命周期与所有权

应用拥有服务、Store 与路由。路由提交创建页面作用域；页面内的 GameCanvas 管理浏览器驱动、场景、输入和资源。离开页面时按所属 Scope 清理，暂停则保留仍需响应的 HUD。

资源以租约持有，异步任务用取消信号和提交代次控制晚到结果。预加载只加载代码，不挂载页面、不启动游戏。不要为同一个 Canvas 再创建一套帧循环。

10 个包，各司其职

包简称 职责
app 组件、响应式、Store、路由与网页游戏应用能力。
core / ecs 固定步、系统排序、模块、清理与实体数据。
browser / renderer-2d / input 浏览器驱动、Canvas 绘制与输入采样。
assets 加载共享、持有和取消。
net / net-server 类型化传输边界与 Node WebSocket 承载。
tooling CLI、三文件关联、类型诊断与 Vite 构建。

全部包名以 @xiaobaibaifqy/jingchuanchu- 为前缀。只有服务端需要 ws；tooling 是开发依赖。应用不内置具体账号后端、房间规则或状态同步协议。

产品边界

仅面向网页 2D 游戏，使用现有 Canvas 2D 后端。不提供 3D、编辑器、复杂刚体、骨骼动画、SSR、账号数据库或玩家皮肤上传服务。性能判断必须来自真实测量，静态构建或 Node 模拟结果不能代表设备体验。
