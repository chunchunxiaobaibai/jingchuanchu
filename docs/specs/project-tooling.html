ENGINEERING HANDBOOK

project-tooling：项目、代码生成和构建

模块边界、所有权、取消语义及直接验收要求。

开发工具负责项目配置、代码生成、模板编译和独立交付。运行时包不依赖 Vite、Less、HTML/CSS 解析器或 TypeScript 编译器。日常命令见CLI 与项目配置。

项目配置契约

当前 application 项目采用 jingchuanchu.json 的 schemaVersion:2、profile:application、preset、style 和 paths。配置解析只读且结果冻结；未知版本、profile 或路径字段应明确报错。配置只选择检查与生成规则，不移动业务文件。

paths 为 app、pages、game、components、themes、account 的项目相对位置，默认对应 src 下同名目录。拒绝绝对路径、盘符相对路径、dot 段、非 kebab-case 段和相互重叠的根。Windows 分隔符与开头 ./ 可规范化。通过 realpath 检查最近存在祖先，拒绝符号链接或 junction 越界。可选目录不自动创建。

检查与依赖边界

检查已有 src 与配置路径内文件。app 装配页面、游戏和服务；pages 可访问游戏与公共组件；公共 components 不导入 app、pages、game、account 内部或 Engine；game 不依赖 DOM、app 和 pages。

使用 TS AST 与 tsconfig 别名解析 import、reexport 和静态动态 import，再检查依赖方向。无法分析的动态路径和内部源码路径应在原文件定位。结构检查不替代模板类型检查、tsc 或 Vite 构建。

生成与注册

create 的 singleplayer/client 使用完整 templates/browser 参考应用，core/server 不生成 UI。组件和页面生成同名 TS/HTML/CSS 或 Less；页面拥有私有组件与场景，Store 归 game 域，主题归 themes。只在业务实际存在时生成目录。

page 需 route；component 需 page 或 shared；scene 需 page；store 需 domain；theme 可 extends。页面注册采用动态 import，组件、场景、Store 和主题仍需显式装配。名称拒绝穿越和 Windows 保留设备名，不接受与生成种类无关的参数。

路由注册器只修改可静态分析的 application.defineRoutes 声明，支持命名别名和顶层 const 数组。检查嵌套路由的全路径模式与 name 冲突；动态构造、spread、未知字段或多个候选声明提供手动接入诊断。

多文件写入与失败保护

写入前完整预检同名 TS、HTML、CSS、Less 与路由冲突；每个目标重新验证 realpath 归属。以独占方式创建文件并登记本次写入。失败只回收本次新增文件和空目录，已有业务不应受损。

页面文件先完成，再更新路由注册表；更新前校验原文未被外部改动。失败尝试恢复本次修改。不可分析或冲突时应在任何写入前拒绝，不能通过正则猜测注册位置。

本地安装与独立消费

create/add 的 bundle 解析校验 manifest、重复包与文件、包名、摘要、版本和内部依赖闭包。固定版本和 ^目标版本须与配套套件匹配；缺失、循环或版本冲突在写入前拒绝。

已校验字节复制到 vendor，package.json 写相对 file 依赖，tooling 放 devDependencies。已有同名同摘要文件可复用，不同摘要拒绝覆盖。add 保留无关依赖与锁文件，并写 jingchuanchu-packages.json 记录版本和摘要；不自动执行 npm install。

vendor 只保存引擎包。Vite、TypeScript、Less、ws 等外部依赖仍需 registry 或缓存；不能据无外部依赖的夹具宣称所有项目完全离线安装。

编译与诊断

编译器识别具名导入的 defineComponent/definePage、静态元数据和同名三文件。明确 templateUrl/styleUrl 时按指定资源解析。缺资源、同名 CSS/Less 歧义、非法绑定及类型错误必须指向原 HTML 或 TS 文件。

模板生成虚拟 TS 并维护源码映射；Less/CSS 与配套 HTML 参与监听。当前允许整页重载，不承诺保留状态 HMR 或独立语言服务。跨字段关联的类型限制需在 API 契约中明确。

直接验收

  • CSS 与 Less 单机项目可独立生成、check、tsc 和 build，产物包含真实动态页面块。
  • page/component/scene/store/theme 进入正确目录；冲突和注册失败不留下部分业务。
  • 复制 vendor、package.json 与锁文件后可以重建引擎依赖；浏览器单机未引入服务端依赖。
  • 模板、主题、路由与路径诊断定位原业务文件。生成项目运行不依赖仓库绝对路径或 source 条件。
  • 套件携带独立 HTML 手册、许可、版本及摘要；本地构建不会自动上传远端。

定向测试见 scaffold、component-template 和 project-structure 相关用例。实际包消费由 scripts/verify/application-package.ts 验证；浏览器体验另行验收。
