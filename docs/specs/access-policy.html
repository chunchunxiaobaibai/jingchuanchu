ENGINEERING HANDBOOK

access-policy：权限策略与路由集成

模块边界、所有权、取消语义及直接验收要求。

公共边界见 SPEC。位置：runtime/access.ts；依赖 auth-session。由 app-config 把策略接入 Router 的通用守卫，Router 不反向导入账号代码。

当前公开判断入口

从 application 子入口导入 AccessService、AccessPolicy、AccessDecision。实例由业务已有 defineService 工厂组合 AuthService，不创建全局服务：

ts
const access = new AccessService({
  auth,
  keys: ['play', 'edit'] as const,
  permissions: (user) => user.permissions,
});
access.can({ session: 'required', all: ['play'], any: ['edit'] });
const decision = await access.check({ session: 'required', all: ['play'] });

keys 定义有限、非空且不重复的权限键；permissions 同步选择经过 AuthProvider decoder 校验的展示身份中的权限列表。未知权限声明、异步或抛错的选择器均拒绝，不从本地角色名称自动授予权限。can 只读当前状态，不请求恢复；check 显式等待 ensureSession，复用已有恢复去重。两者都不缓存授权，下一次判断读取当前身份。

策略为 'public' 或 {session:'required',all?,any?}。缺失/非法策略和未知键在恢复前拒绝；all 与 any 同时出现时均需满足，all:[] 为真、any:[] 为假，不填两组只要求已确认身份。公共策略不恢复会话。check 当前返回 allow 或 deny(reason,cause?)，reason 区分 anonymous、session-failed、cancelled、forbidden、invalid-policy、invalid-permissions；can 对任何拒绝均返回 false。unknown/restoring 时同步 can 拒绝，显式 check 等待；选择器重入导致身份代次变化同样拒绝旧结果。应用退出后服务不再允许判断为通过。

AccessService.check 本身不重定向；createAccessGuard 将匿名映射到登录目标、权限不足映射到 forbidden，其余失败保持 deny。安装 bindAccessRouter 后身份失效会同步释放受保护页面与旧导航；这些功能仍不代替服务端校验。

权限模型

业务定义有限权限键，角色可映射到权限；AccessService.can 返回展示用判断，check/守卫可等待会话并返回 allow、deny(reason)、redirect(target)。支持 all/any，若同时指定则两组都满足。未知键、缺失策略或未确认身份不允许受保护操作。

资源归属等策略可使用服务器返回结果，不由本地角色字符串推断所有资源的真实权限。公共组件使用 allowed/disabled 输入或公开能力，不强依赖某个账号 Store。

当前路由装配

ts
router: {
  guards(context) {
    return [createAccessGuard({
      access: context.useService(Access),
      resolve: context.resolve,
      anonymous: (returnTo) => ({ name: 'login', query: { returnTo } }),
      forbidden: { name: 'forbidden' },
    })];
  },
}

Access 是业务 defineService 定义，工厂组合前述 AccessService 与 AuthService；各应用分别解析。router.guards 是同步工厂，每次挂载调用一次，提供现有服务 scope/signal/own/useService 与类型化 resolve。返回通用 RouteGuard 数组，依次在离开守卫之后、路由记录守卫及页面加载/prepare 之前运行；Router 只认识通用守卫，不导入账号代码。直接使用 createRouter 时也支持 guards 数组。工厂失败会回收历史驱动与已登记资源。

createAccessGuard 遍历 matched 各层自己的 meta.access，缺失也拒绝；子 public 不绕过父 required。导航取消只停止本次权限等待，保留其他调用共享的 ensureSession 请求。匿名回调收到已经由当前路由解析器确认的 fullPath，包含参数/query/hash；失败或权限不足不会一律当登录。登录/forbidden 目标必须能由当前解析器解析，且是不同的、整条父子链显式 public 的非 redirect 路由；非法外部地址、缺失路由与跳转环拒绝。登录后从查询串取出的返回目标使用下述独立辅助入口校验。

登录成功后使用公开 resolveAccessReturnTarget；输入为 Router 已解码一次的 query.returnTo，不手动 decodeURIComponent：

ts
const target = resolveAccessReturnTarget(router.current()?.query.returnTo, {
  resolve: router.resolve,
  login: { name: 'login' },
  fallback: { name: 'home' },
});
await router.replace(target);

login/fallback 必须为不同路径、整条 matched 链显式 public 且没有 redirect 的应用路由；配置无效抛 AccessError(return-target-config)。返回值只接受单个内部绝对路径字符串，经实际应用 resolve 规范化并匹配；外部地址、数组/对象、仍把开头斜线编码为 %2F 的字符串、无效或未匹配路径、登录路径（无论 query/hash）及 redirect 记录回退到 fallback。合法动态参数/query/hash 保留，不做二次解码。此方法只解析导航目标，不预先执行路由 redirect 或授权；合法的受保护目标仍须通过下一次 router.replace/push 的全部权限守卫。

在应用根组件的 setup 中安装身份生命周期绑定，scope 使用根组件/应用的完整生命周期，不能仅绑定到临时页面：

ts
const auth = context.useService(Account);
bindAccessRouter({ auth, router: context.router, scope: context.scope });

此绑定与 router.guards/createAccessGuard 配套使用。AuthService.invalidate/login/logout/dispose 触发身份清理时，若 current 或 pending 的任一匹配记录并非显式 public（包括缺策略），同步调用 Router.invalidate：取消等待、清空 current 并释放整个页面候选/页面 owner，已有 Canvas、音频、资源和网络活动依既有 owner 协议退出；离开守卫没有否决权。公共 current 且没有受保护 pending 时保留页面。身份切换一律先失效旧视图，即使新账号之后仍具同样权限，也必须显式重新进入。load/prepare 不响应取消的晚到结果不会构造或提交旧页面。scope 退出注销绑定，不为账号服务建立永久全局监听。

Router.invalidate 是不依赖认证模块的通用同步操作：保留 Router/历史驱动/代码缓存，取消当前导航并清空已提交页面；不写 URL、不启动新的登录请求或导航。调用方可在身份操作完成后显式 router.replace 到登录页/公共页，后续导航重新执行全部守卫；因此清理期间不会恢复旧会话。退出后的 invalidate 幂等无操作。页面清理失败仍先清空旧路由状态并尝试已有 owner 的全部清理，抛带来源的 RouteError；经 AuthService 清理登记聚合报告，不能伪装清理成功。

服务端撤销或权限更新的通知必须由业务 Provider/请求层触发 auth.invalidate（401 与 403 分别处理）；框架不自动轮询远端，也不信任在已下载页面代码里保存的旧判断。未安装身份绑定的独立 createAccessGuard 仅负责导航准入，不宣称已挂载页面能自动驱逐。Node 检查只验证作用域回收与晚到结果处理，没有实际浏览器/Canvas 画面或后端撤销验收。

有应用全局守卫时 intent/idle 自动预加载保守跳过（protected），不为预加载运行守卫；显式 preload 仍只取页面代码，不表示拥有访问权限。

路由策略

认证应用路由在 meta.access 中显式声明 public 或 {session:'required',all/any}，由 app 装配的权限守卫读取。Router 的通用 meta 不导入 AuthService。父子条件累计，子 public 不解除父限制。守卫在页面准备/Canvas 活动之前执行；直接 URL、链接、程序导航及前进后退使用同一规则。

未知身份等待 ensureSession；匿名进入业务登录流程；已认证但无权限进入 forbidden 结果。登录返回目标限合法应用内 RouteTarget，避免外部重定向和循环。401 会话失效与 403 无权限分别处理，不把所有错误都当成重新登录。

会话被撤销后重新检查当前受保护页面，并停止其用户活动；已下载页面代码或已挂载页面都不是继续访问的依据。纯单机模式不要求每条路由声明账号策略。

真正的 HTTP/WebSocket 操作必须由服务端验证身份及资源权限。示例同时包含客户端拒绝体验和服务端拒绝结果；浏览器 Store 或按钮被篡改不能改变后端结果。

直接验收

Q1：匿名/恢复中/无权限产生不同导航结果，拒绝时不创建页面准备或 Canvas。

Q2：嵌套策略累计、权限变更驱逐、内部返回目标及授权前后导航都可验证。

Q3：假后端仍拒绝绕过前端守卫的请求/消息，不能以隐藏按钮代替测试。

测试：tests/access-policy.test.ts、Router 集成 fixture；实际业务权限规则由业务项目提供。
